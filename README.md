# cloudensis.com

Cloudensis合同会社のコーポレートサイト。

Hono の JSX で描画し、Cloudflare Workers にデプロイしている。

## 必要なもの

- Node.js: `.node-version` に書かれたバージョン（CI も同じファイルを参照する）

## 開発

```sh
npm ci
npm run dev
```

http://localhost:5173 で開発サーバーが起動する。

| コマンド            | 内容                                                          |
| ------------------- | ------------------------------------------------------------- |
| `npm run dev`       | 開発サーバーを起動する                                        |
| `npm run lint`      | Biome で lint と format を検査する（`npm run format` で修正） |
| `npm run typecheck` | Workers の型を生成し、`tsc` で型を検査する                    |
| `npm test`          | Vitest でテストを実行する                                     |
| `npm run build`     | SSG と Worker をビルドする                                    |
| `npm run preview`   | 本番と同じ構成でビルドし、ローカルで配信する                  |

## 構成

| 種類                                                    | 定義            | 本番での配信                                                                    |
| ------------------------------------------------------- | --------------- | ------------------------------------------------------------------------------- |
| ページ（トップページなど）、`robots.txt`、`sitemap.xml` | `src/ssg.tsx`   | ビルド時に `dist/ssg` へ静的ファイルとして書き出し、Worker を経由せずに配信する |
| 404 / 500 ページ                                        | `src/index.tsx` | Worker が描画する                                                               |
| 画像・favicon                                           | `public/`       | 静的ファイルとして配信する                                                      |

開発時（`npm run dev`）は、SSG のページも Worker が描画する。そのため、静的ファイルのヘッダー（`public/_headers`）やキャッシュの挙動は開発サーバーでは再現しない。これらを確認するときは `npm run preview` を使う。

### ページを追加するとき

1. `src/ssg.tsx` にルートを追加する。
2. 同じファイルの `pagePaths` にパスを追加する（`sitemap.xml` に載る）。

## デプロイ

| 環境       | 方法                                                                             |
| ---------- | -------------------------------------------------------------------------------- |
| 本番       | GitHub で release を公開すると、テストの後に `Deploy` ワークフローがデプロイする |
| プレビュー | Actions タブから `Preview` ワークフローを手動で実行する                          |

`main` へのマージだけでは本番に反映されない。

## 依存パッケージ

- Dependabot が週に 1 回、更新の PR を作る。major 以外は自動マージが有効になる（`main` のブランチ保護で `test` ジョブを必須チェックにしておくこと）。
- `.npmrc` で install スクリプトの実行を禁止し、公開から 3 日たっていないバージョンを入れないようにしている（サプライチェーン攻撃への対策）。
